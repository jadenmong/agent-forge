# AgentForge — 系统知识体系、面试训练与求职材料（最终版 v2.0）

> 项目基准日期：2026-10-14；本周 10 月 18 日前验收，下周 10 月 19 日开始投递。
> 面向岗位：**AI Agent 应用开发工程师 / LLM 应用工程师 / Agent Runtime 或平台工程师**，不是“Python 工程师专岗”。
> 学习策略：编程语言是载体，关键能力是 Agent 的执行模型、状态、工具协议、可靠性、评测、架构与工程权衡。所有代码由 Codex 完成，但候选人必须独立讲清、审查、验收和回答追问。

## 1. 七层知识体系（与源码/项目验收对应）

| 层级 | 需要理解的核心问题 | AgentForge 对应源码/行为 | 面试达标标准 |
|---|---|---|---|
| 1 LLM 接口 | Token、上下文、结构化输出、工具调用、模型续传 | ModelAdapter、Responses 适配器 | 不看提示讲出完整 function-call roundtrip、错误处理 |
| 2 Agent Runtime | Agent 与 Workflow 差异、ReAct Loop、行动选择和终止、预算 | RuntimeEngine、RunState | 能手绘循环，讲清止损/超时/限制机制 |
| 3 Tools 与 MCP | Tool Schema、Registry、MCP Host/Client/Server、权限 | ToolRegistry、MCP Adapter | 能解释 schema 校验如何衔接模型响应与实际执行 |
| 4 状态与上下文 | Run state、短期 memory、Checkpoint、幂等、上下文截断 | SQLite Checkpoint、model_resume_state | 能解释崩溃恢复边界和重复副作用的处理 |
| 5 编排与安全 | 确定性 Workflow vs Agent、HITL、注入攻击、最小权限 | Approval Gate、policy、state machine | 能推理恶意输出与重复审批案例 |
| 6 评测与观察 | Event/Span/Trace、Golden set、baseline、p95、成本 | Trace Studio、Eval Runner | 能区分 Mock 测试与 Live 模型质量结果 |
| 7 系统设计 | REST/OpenAPI 跨语言接入、任务队列、租约、并发、分布式恢复、云化与多租户 | API_CONTRACT/DECISIONS/FAILURE_MODES | 解释为何 API 语言无关不等于多语言 Runtime，并能推导生产扩展 |

**明确范围：** 本周 Runtime 用 Python 编写，前端使用 React + TypeScript，跨语言使用能力表现为 REST/JSON/OpenAPI 与 MCP 互操作；不开发 Java/Go/Node 原生 Runtime。**加深但本周不要求编码实现：** 向量 RAG（chunking/embedding/hybrid/rerank/Recall@K）、长期记忆污染、Multi-Agent handoff、A2A、上下文压缩与语义缓存；能够解释典型场景即可。如果代码未实现，这些只能写在知识掌握或展望，不写进项目成果。

## 2. 每日学习节奏（Codex 可以并行执行）

每天采取两轮：
- **第一轮 45–60 分钟**：针对当天模块，先画图并口述机制，再看 Codex 的关键源码入口，检查数据流。
- **第二轮 45–60 分钟**：运行验收 Demo、注入一种故障、检查事件与数据库实际结果、做面试问答。
- **夜间 20–30 分钟**：录制或口述 3 分钟技术说明，列出 2–3 个当日理解不清之处。

如果一天只有 1–2 小时，优先第二轮的核心验收与面试讲解，而不是阅读更多框架教程。

### Day 1 10/14 — Agent Loop

必须掌握：LLM 本身不执行工具；模型产出工具调用意图，Runner 校验并执行；工具结果再送回模型；“是否结束”由最终响应和运行时限额共同约束。Agent Loop 是一种受约束的状态转移，不是随便 while True。

动手审查：`run()` 入口、`ModelAdapter`、`ToolDispatcher`、stop_reason；从 Mock 多工具示例中指出 5 个连续事件及其来源。

闭卷问答：
1. 传统 Workflow 与 Agent 的边界是什么？什么场景不该用 Agent？
2. 为什么模型生成 tool call 不等于已经执行 tool？
3. 若模型一直请求相同工具，如何检测与终止？
4. 一个模型返回 2 个工具请求，你如何安排顺序与并发？
5. 发生工具异常时，要把什么信息反馈给模型，什么信息留在服务端？

### Day 2 10/15 — MCP + 模型协议

必须掌握：Function Calling 是模型与应用的调用契约；MCP 是向 Agent/客户端暴露工具等能力的互操作协议。MCP Server/Client 和模型本身不是同一个概念；工具声明可信度与工具输出可信度也不同。

动手审查：MCP tool discovery、参数验证、错误映射、OpenAI Responses `call_id` 映射，比较 Mock / Live 适配器。核对 2026-07-28 MCP 规范与 v2 SDK，不套旧教程；另核验 `/openapi.json` 和 `curl` 示例，让非 Python 程序也能发起任务。

闭卷问答：
1. Function Calling 和 MCP 是竞争关系还是互补关系？
2. MCP Server 能不能决定是否绕过应用的审批策略？
3. MCP v2 2026 新规范与 2025 初始化模式最显著的不同是什么？
4. 模型调用的 `call_id` 为什么必须原样关联结果？
5. 恶意 MCP 返回值要求 Agent 执行其他敏感工具，如何防御？
6. 平台 Runtime 用 Python 写，为什么仍能服务 Java/Go/TypeScript 开发者？这与跨语言执行插件有何区别？

### Day 3 10/16 — Checkpoint/HITL/Context

必须掌握：Checkpoint 是一次执行的持久化状态；Memory 是可跨步骤/会话复用的信息；日志是发生过的事件；幂等保障允许安全重试的副作用。这四者不同。

动手审查：状态转换表、批准前写入 0、重复批准写入 1、重启后 pending approval 仍可恢复，未知副作用如何处理。

闭卷问答：
1. Checkpoint 和长期 Memory 区别是什么？
2. 任务暂停等待一天，要保存哪些信息才能继续？
3. 为什么存了 Checkpoint 不代表任意工具可安全重试？
4. 审批按钮点两次造成并发写入，靠 UI 禁用够不够？
5. 什么是 TOCTOU，为什么审批要绑定工具参数？

### Day 4 10/17 — Evals/Observability/Security

必须掌握：Agent 质量评测与 Runtime 正确性测试分开；不能只看回答“像不像正确”；要定义任务达成、工具准确性、权限违规、耗时/成本等维度。

动手审查：EvalCase 字段、Mock vs Live 标记、失败测试、Trace event 恢复、Model token usage 精度边界、敏感信息脱敏。

闭卷问答：
1. 50 条 Mock 回归全绿，能否宣称 Agent 准确率 100%？为什么？
2. Tool-selection accuracy 如何定义？有哪些标注问题？
3. “LLM as judge” 有哪些偏差，如何通过规则/人工校验补足？
4. Prompt Injection 为什么不能只靠系统提示词防御？
5. p95 延迟在有人工审批等待时如何计算才有意义？

### Day 5 10/18 — 架构、代码审查与模拟面试

必须掌握：能画出从用户任务、模型调用、工具发现/执行、Checkpoint、审批、恢复、Trace、评测的完整路径；能讲清自研 vs 框架、SQLite vs Postgres、Mock vs Live 的权衡。

当天安排：
1. **10 分钟项目讲解**：产品问题、用户价值、架构、核心数据结构、demo、评测、局限。
2. **20 分钟项目深挖**：检查 Loop、模型 continuation、幂等/状态、MCP 安全、失败恢复。
3. **20 分钟系统设计**：把单机平台扩展到 1000 个并发长任务，需要怎么改？
4. **20 分钟编码/阅读**：不用 Codex，读 40–80 行真实 `run`/`approve` 代码，指出一处 bug 或解释关键流程；需要现场编码的岗位再加最小工具调用伪代码。
5. **复盘**：把没答上的知识点写成 1 页，重新考核一次。

## 3. 高频问题清单（项目深挖参考答案要点）

| # | 面试题 | 必须命中的答案要点 |
|---|---|---|
| 1 | 什么才叫 Agent？ | LLM 决策 + 工具/环境反馈 + 多步执行控制；与固定 workflow 的差异 |
| 2 | Agent Loop 的核心流程？ | 模型调用、决策解析、校验、执行、结果写回、终止；循环上限 |
| 3 | 为什么不全部使用 LangGraph？ | 为了展示自研 Loop；实际生产需要比较生态、成本和可靠性，不是拒绝框架 |
| 4 | 为什么不直接把所有工具提供给模型？ | 工具噪声、token、安全边界、最小权限、检索式工具暴露 |
| 5 | Tool call 参数校验失败怎么办？ | 拒绝执行、结构化错误、记录 trace、有界重试/模型修正 |
| 6 | 工具调用重试如何避免副作用重复？ | 幂等键、唯一约束、调用状态、补偿/核对；不能靠简单重试 |
| 7 | 什么是 Checkpoint？ | 持久化可恢复的执行状态和模型续传信息；与 event log 不同 |
| 8 | 如何恢复待审批任务？ | pending 工具调用+参数快照+approval id + 事务状态；恢复时只执行被批准项 |
| 9 | 恢复一定 exactly-once 吗？ | 否；跨外部系统无法普遍保证，需幂等/对账/人工确认 |
| 10 | HITL 放在哪里？ | 决策与执行之间的策略闸门；审批不能只由 prompt 决定 |
| 11 | MCP 的 Host/Client/Server？ | 应用拥有 Host，MCP Client 管连接/调用，Server 暴露工具；协议不是权限判断器 |
| 12 | MCP 与 Function Calling 差别？ | 后者模型输出调用格式，前者统一工具/资源暴露方式，可互补 |
| 13 | MCP 连接状态可当 Run State 吗？ | 不应；2026 新规范核心趋向按请求无状态，任务连续性由应用维护 |
| 14 | 你怎么处理工具异常？ | 结构化错误、分类、有限重试、明确终止、trace 与用户说明 |
| 15 | Agent 死循环怎么处理？ | max_steps、重复签名、时间/token/tool budgets、有界 fallback |
| 16 | Context Window 不够怎么办？ | 摘要/裁剪、保留关键约束与工具结果、检索补充、不能破坏 continuation 协议 |
| 17 | Memory 与 Context/Checkpoint？ | Context = 当前模型输入；Memory = 长期可复用知识；Checkpoint = 执行快照 |
| 18 | RAG 怎样优化召回？ | 分析数据/切分/查询重写/混合召回/rerank/Recall@K 与 citations |
| 19 | 运行轨迹 Trace 中记录什么？ | event/span、耗时、tool name、脱敏输入输出、结果、预算；不暴露隐式推理链 |
| 20 | 如何证明效果提升？ | 冻结数据集、baseline、版本/模型配置、定义准确指标、重复测量 |
| 21 | Mock 全绿意味着什么？ | 证明协议和控制逻辑，不能证明真实模型推理质量 |
| 22 | Live Eval 如何防样本污染？ | 开发集/测试集隔离、固定版本、失败分类、记录标注来源 |
| 23 | LLM 评审器可靠吗？ | 有偏差与方差，优先可规则判定；人工抽样与一致性检查 |
| 24 | Prompt Injection 怎么防？ | 数据/指令信任边界、权限最小化、输出校验、审批、安全工具约束 |
| 25 | 为什么用 SQLite？ | 本地单机可复现；并发/HA/迁移到 Postgres 后需考虑锁、事务、队列 |
| 26 | 1000 个并发长任务架构？ | 队列、worker、run lease、租约续期、幂等、共享存储、分布式 trace |
| 27 | 如何做取消与超时？ | cancel flag/信号、可中断点、工具超时策略、终止清理、注意外部副作用 |
| 28 | 真实模型成本怎么统计？ | provider usage + 价格表 + 费用版本；不完整 usage 标为 unknown |
| 29 | 为什么选择审批采购场景？ | 可完整覆盖读取、计算、敏感写、审批、恢复、可重复评测，不需真实业务凭证 |
| 30 | 这个项目有哪些明显局限？ | 本机单实例、无远程隔离、不支持高并发、模型评测样本有限、无通用安全沙箱 |
| 31 | 如果面试官要求现场改 bug？ | 先复现失败、定位 trace/run event、写最小测试，再修复而非盲改 |
| 32 | MCP tool 注入要求窃取 secrets？ | 模型/工具内容视不可信，应用层 allowlist、禁用任意网络/文件/命令并审计 |
| 33 | AgentForge 是不是 Python 工程师专用？ | 不是；产品用户跨语言，但当前服务端 Runtime 用 Python，实现是工程选型 |
| 34 | REST/OpenAPI 是否等于多语言 Runtime？ | 不是；Java/Go/TS 可通过 HTTP 调用现有 Python Runtime，但不能原生执行其插件 |
| 35 | MCP 和 REST 各解决什么？ | REST 暴露平台控制 API；MCP 标准化工具等上下文能力，两者可在同一系统共存 |
| 36 | 想支持 Java/Go 原生工具执行应如何演进？ | 设计版本化工具协议、远程 worker、鉴权、隔离、租约与幂等；不是简单改语言声明 |

## 5. 可直接演示的五分钟脚本

- **0:00–0:30**：解释 AgentForge 解决的问题：Agent 决策不确定，必须让执行流程可检查可控制。
- **0:30–1:10**：打开 Workbench，展示 Agent preset（本地 Mock）；输入采购比较任务，运行。
- **1:10–2:00**：Trace 中指出 Model Request、Tool Invocation、Tool Result 与限额计数，解释真实工具执行由平台负责。
- **2:00–3:00**：触发创建采购草案；系统停在 WAITING_APPROVAL；演示拒绝不会有 DB 写入，再跑一次批准后只创建一份草案。
- **3:00–3:40**：在审批等待阶段重启服务，恢复同一 run/approval；解释恢复边界与幂等。
- **3:40–4:30**：打开 Evals 展示 Mock 回归统计、失败分类、一次注入/超限测试；如有 Live 结果清楚分开展示。
- **4:30–5:00**：总结技术权衡与不支持的生产能力，明确下一步可如何演进到多 worker 和 Postgres。

## 9. 语言无关定位如何回答面试官

**Q：你为什么把 Python 作为 Runtime 语言？** 这不是岗位能力的边界，而是交付策略：本周需要验证底层执行、MCP 接入和评测，Python 的 SDK/测试生态缩短 MVP 时间。核心设计采用清晰的协议与状态契约，适用于不同实现语言。

**Q：Java/Go 工程师如何使用 AgentForge？** 使用 REST/JSON/OpenAPI 发送 Run、查询 Trace、完成审批；他们不需要写 Python 客户端。当前**服务端部署仍依赖 Python 环境或 Docker**。

**Q：MCP 为何重要，和跨语言关系是什么？** MCP 标准化工具等能力的发现与调用；不同语言可分别实现兼容的 Server/Client。但本项目仅验收官方 Python SDK v2 示例，不宣称已测试任意语言 SDK。

**Q：支持任意语言的工具需要怎么做？** 下一阶段需要远程工具执行协议、隔离运行节点、版本与权限管理、租约及重试控制。本周只实现本地工具和一个本机 MCP 实例。

**Q：这种项目与真正的 AI Agent 应用岗有什么联系？** 应用开发的难点不止提示词或模型调用，而是把不确定决策纳入可控的执行系统；Runtime、工具、状态、审批、Evals 是横向通用能力。
