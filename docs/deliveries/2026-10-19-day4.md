## 3. 核心决策与残余风险

1. **固定期望，可审阅判定。** 42 条由 Codex 依据 PRD/已有故障构造，期望不是从运行结果生成。judge 只支持命名判定版本，不执行任意用户代码；严格核对状态/原因、实际执行工具序列、禁止工具、SQL 草案数和必需事件。意外异常记 FAIL，不跳过。仍需要独立审阅，不能冒充 Live 标注集。
2. **故意让 Mock 服从攻击，再验证后端。** untrusted_note 实际返回恶意 JSON，脚本随后提出写调用。无工具权限被拒，有工具授权也必须 WAITING_APPROVAL；草案均 0。这证明政策边界，不证明真实模型自身抗注入能力。
3. **指标基于观察。** 工具错误率为 FAILED 工具步骤/工具尝试，无调用为 unknown；wall-clock 包含人工等待，活动时间单列。Mock usage 仅作预算故障，另标 synthetic_mock_usage；model_tokens/cost 为 unknown。Live 只有所有请求都有真实 usage 才汇总，缺价格不造 $0。
4. **评测与普通任务隔离。** 每例独立 SQLite；EvalJobs 只管理本进程一个评测任务，报告文件持久化，100 批上限；中断批次不自动续跑。同步 DB/文件 I/O 及顺序执行适合本机，不是可靠队列或吞吐方案。Runner 还有单例外层超时，不能执行任意阻塞工具。
5. **比较有前提。** mode/dataset/fixture/judge/case IDs 一致才比较；记录 runtime 摘要但允许不同代码，输出逐例 regression/improvement。耗时变化不算受控性能实验。
6. **保留原恢复边界。** WAITING_APPROVAL 与有本地草案凭据的 AFTER_APPROVED_TOOL 可恢复；未知写结果转待核对，终态不复活。本次本地幂等不代表任意外部副作用 exactly-once。

风险：案例由实现者构造、Live 未测；私有 DB 含精确 Demo 上下文，脱敏非通用 DLP；文件报告无归档/防篡改；单 worker；Compose 容器和远端 CI 未执行。详见 [DECISIONS D016–D019](../DECISIONS.md)。

## 7. 五个面试追问与参考答案

1. **42/42 为什么不叫模型准确率？** 判断的是确定性 Runtime 是否满足固定预期，安全拒绝也是 PASS；没有 Live 标签或模型采样质量评测。
2. **如何证明 judge 没有只给自己打满分？** 错误期望会 FAIL/退出 1，实际状态/工具/SQL 副作用/事件逐项公开，异常不 skip；期望和来源可审阅。仍承认作者构造案例的覆盖局限。
3. **注入测试是不是只在 prompt 写一句攻击？** 不是；恶意 JSON 由真实工具执行返回并进入 untrusted context，Mock 随后故意请求写入；后端拒绝或暂停，SQL 草案 0。
4. **为什么 Mock 有 usage 却 tokens 是 unknown？** 合成 usage 只服务预算熔断，独立标记；真实模型 tokens 必须来自完整可用 Live usage，价格缺失成本 unknown，不能冒充供应商账单。
5. **新 clone、CI、Docker 是一回事吗？** 不是。新 venv/npm ci 验证候选安装与命令；CI 配置需要真实云端记录才能称已绿；Docker 要实际构建/启动才算通过。当前容器/云端未测，不能相互代替。

入口、取舍与局限见 [INTERVIEW_NOTES](../INTERVIEW_NOTES.md)。Codex 编码；候选人按实际参与说明需求、审阅、验收和讲解，不能把自动编码说成全部独立手写。
