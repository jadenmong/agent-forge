# AgentForge Day 3 交付 — 2026-10-18

## 1. 结论、架构选择与边界

Day 3 要求已在本机 Mock/合成数据范围完成：SQLite 持久化、绑定参数的人工审批、同库草案幂等写入、安全等待点恢复、浏览器 Trace。先通过 Day 2 的 107 项基线，最终 **143 项通过、0 失败**。真实 API 进程重启、浏览器操作、curl 与 SQL 行数均实际验证。

核心仍是自研 `RuntimeEngine`。新增 SQLAlchemy==2.0.55，SQLite WAL/外键/busy timeout；短 `BEGIN IMMEDIATE` 事务配合 Run revision 及数据库唯一约束。没有框架 Runner、额外队列或生产数据库。

普通 Registry dispatch 不能执行敏感工具；`create_purchase_draft` 是唯一内置的事务写路径。批准接口只收 approval_id/decision，从数据库绑定参数，在一个事务里提交审批、草案、工具结果及 checkpoint。SHA-256 用于一致性校验，不是身份签名。不同 Run 创建的新调用不做业务语义去重。

**能恢复什么：**

- `WAITING_APPROVAL`：重启后同一 run_id、approval_id、具体参数、原任务上下文；批准后继续模型。
- `AFTER_APPROVED_TOOL`：重启发现中断时，仅在真实草案凭据、已批准决议、已完成调用、上下文结果和冻结配置一致后，显式 resume；不重做写入。

**不能恢复什么：**

- 模型/只读工具执行中的任意位置，包括本次未开放的读工具完成断点；标为 INTERRUPTED，resume 拒绝。
- 结果未知的高风险写调用；转 RECONCILIATION_REQUIRED，禁止盲目重发；尚无核对控制 API。
- COMPLETED/FAILED/CANCELLED 终态；损坏 checkpoint 失败关闭。
- 任意外部 HTTP/ERP 副作用；本例只有本地同库模拟写入幂等，不能声称 arbitrary tool exactly-once。

剩余限制：单进程/单 worker，无可靠队列；同步 SQLite 会短暂阻塞事件循环，最多 5 秒锁等待；自动初始化仅空库到 schema v1，无通用升级迁移器；脱敏是已知字段规则，私有 DB 仍保留精确 Demo 上下文，无数据库加密/通用 DLP。Live 外部 API 未测。全部业务数据为合成数据，不下单、不执行任意命令。

取舍及替代方案详见 [DECISIONS D012–D015](../DECISIONS.md)。

## 6. 五个面试追问与参考答案

1. **prompt 要求审批为什么不够？** 模型只是请求者。Registry 普通执行拒绝敏感权限，Runtime 先持久化 waiting；只有后端批准事务校验绑定调用/参数/权限后才 INSERT。前端改文本或请求参数无法放行。
2. **并发批准如何避免第二份草案？** BEGIN IMMEDIATE 后重新读决议；同一事务写审批/草案/结果/checkpoint，数据库再用三个唯一约束兜底。12 请求并发首次批准只有一个首次决定，重复仍 SQL COUNT=1；范围只限同库模拟副作用。
3. **checkpoint 为什么不只存消息？** 还要保存冻结配置、pending 调用、适配器描述、已执行结果、安全点和关联审批。OpenAI 必须保留合法 call_id/加密续传协议项，不能拍平成普通聊天。恢复有边界，终态不复活。
4. **为什么 SQLite，何时需要换？** 本机单用户下短事务和唯一约束易复现/解释；同步操作有阻塞，单 worker 无可靠队列。如果目标变为多节点调度，需要重新设计所有权、队列与外部幂等协议，本周不提前实现。
5. **你如何证明实测与准确贡献？** 提供 JUnit、真实进程重启、HTTP 并发、SQL 行数及浏览器截图，不把 Mock 当 Live 质量。Codex 编码；候选人参与需求、技术取舍、审阅、验收与讲解，具体个人工作由本人确认。

更完整入口与边界见 [INTERVIEW_NOTES](../INTERVIEW_NOTES.md)。
